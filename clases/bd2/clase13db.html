Instalación y Primeros Pasos en Apache Cassandra

Sesión introductoria para comprender qué es Cassandra, preparar un entorno local y ejecutar las primeras instrucciones mediante Cassandra Query Language (CQL).

1. ¿Qué es Apache Cassandra?

Base NoSQL distribuida

Apache Cassandra es una base de datos NoSQL orientada a columnas anchas, diseñada para almacenar grandes volúmenes de datos en varios nodos sin un punto único de fallo.

Escalabilidad horizontal

En lugar de aumentar únicamente la capacidad de un servidor, se pueden agregar nodos al clúster para repartir datos y carga de trabajo.

CQL

Cassandra Query Language tiene una sintaxis parecida a SQL. Se usa para crear keyspaces, tablas y manipular filas de acuerdo con la clave primaria.

Conceptos esenciales: un nodo es una instancia de Cassandra; un clúster es un grupo de nodos; un keyspace equivale a un espacio lógico con reglas de replicación; y una tabla almacena filas organizadas alrededor de su clave primaria.

2. Guía de instalación para el laboratorio

Para una primera práctica se recomienda usar Docker: es aislado, repetible y evita modificar la instalación local. La documentación oficial también contempla paquetes y archivos tarball para Linux.

1Instala los requisitos

Instala Docker Desktop en Windows o macOS, o Docker Engine en Linux. Si eliges una instalación nativa, Cassandra requiere Java compatible; la documentación oficial indica Java 11 o 17 para las versiones actuales y Python para utilizar cqlsh.

2Crea una red y descarga la imagen
docker network create cassandra-lab docker pull cassandra:latest
3Inicia un nodo local
docker run --rm -d --name cassandra-lab --hostname cassandra-lab \ --network cassandra-lab cassandra:latest

Espera unos segundos a que el servicio termine de iniciar. En una instalación nativa puedes comprobar el estado con nodetool status; el estado UN significa Up/Normal.

4Abre la consola CQL
docker exec -it cassandra-lab cqlsh

Al ver el prompt cqlsh>, ya puedes crear un keyspace y ejecutar CQL. Para detener el laboratorio: docker stop cassandra-lab.

Referencia: guía oficial de instalación de Apache Cassandra y quickstart oficial.

3. Primeros comandos CQL

El siguiente ejemplo crea un keyspace local de práctica, una tabla simple y dos filas. SimpleStrategy con factor de replicación 1 es apropiado para un laboratorio de un solo nodo, no para producción.

CREATE KEYSPACE IF NOT EXISTS academia WITH REPLICATION = { 'class': 'SimpleStrategy', 'replication_factor': 1 }; USE academia; CREATE TABLE IF NOT EXISTS estudiantes ( id uuid PRIMARY KEY, nombre text, curso text ); INSERT INTO estudiantes (id, nombre, curso) VALUES (uuid(), 'Ana', 'Cassandra'); SELECT * FROM estudiantes;

4. Simulación interactiva: primer contacto con CQL

Elige los comandos en el orden lógico para crear un keyspace, seleccionarlo y consultar la tabla de estudiantes.

Cassandra CQL Shell Simulator cqlsh> Selecciona un comando para comenzar.

Meta: crear keyspace → usarlo → crear tabla → consultar tabla.

5. Ejercicios de introducción

Ejercicio 1: Diseña tu primer keyspace

Crea un keyspace llamado biblioteca para un laboratorio de un solo nodo y una tabla libros con isbn como clave primaria, además de titulo, autor y anio. Inserta un libro de ejemplo.

CREATE KEYSPACE IF NOT EXISTS biblioteca
WITH REPLICATION = { 'class': 'SimpleStrategy', 'replication_factor': 1 };
USE biblioteca;
CREATE TABLE libros (isbn text PRIMARY KEY, titulo text, autor text, anio int);
INSERT INTO libros (isbn, titulo, autor, anio)
VALUES ('978-1', 'Introducción a Cassandra', 'A. Rivera', 2026);
Ejercicio 2: Interpreta una clave primaria

Para una tabla de asistencias, ¿qué clave primaria permite consultar fácilmente las asistencias de un estudiante por fecha? Propón una tabla con estudiante_id, fecha y presente.

Una opción introductoria es particionar por estudiante y ordenar por fecha. Así se consulta con WHERE estudiante_id = ....

CREATE TABLE asistencias (
  estudiante_id uuid,
  fecha date,
  presente boolean,
  PRIMARY KEY (estudiante_id, fecha)
);

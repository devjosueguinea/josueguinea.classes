Operaciones CRUD y Configuración de Sharding

Aplica operaciones esenciales sobre documentos MongoDB y diseña una configuración de sharding que permita escalar una colección de manera horizontal.

1. Recordatorio de conceptos

CRUD

Create, Read, Update y Delete son las cuatro operaciones básicas para administrar documentos de una colección.

Shard key

Campo o combinación de campos que MongoDB usa para distribuir los documentos entre los shards.

Componentes

Un clúster sharded incluye shards, servidores de configuración y el proceso mongos como router de consultas.

2. Ejercicio práctico 1: Operaciones CRUD

Trabaja sobre la colección productos de la base tienda. Inserta tres productos, consulta los que tengan stock menor a 10, actualiza el precio del producto Teclado Mecánico a 55 y elimina los productos descontinuados.

// Documento de ejemplo { nombre: "Teclado Mecánico", categoria: "Periféricos", precio: 60, stock: 8, descontinuado: false }
Reto: escribe una instrucción MongoDB para cada operación solicitada. Considera que el producto "Mouse Óptico" está descontinuado.
Solución CRUD
use tienda

db.productos.insertMany([
  { nombre: "Teclado Mecánico", categoria: "Periféricos", precio: 60, stock: 8, descontinuado: false },
  { nombre: "Monitor 24", categoria: "Pantallas", precio: 180, stock: 15, descontinuado: false },
  { nombre: "Mouse Óptico", categoria: "Periféricos", precio: 18, stock: 3, descontinuado: true }
])

db.productos.find({ stock: { $lt: 10 } })
db.productos.updateOne({ nombre: "Teclado Mecánico" }, { $set: { precio: 55 } })
db.productos.deleteMany({ descontinuado: true })

3. Ejercicio práctico 2: Configuración de Sharding

La plataforma PedidosExpress almacena millones de pedidos en la colección ventas.pedidos. Cada pedido posee numeroPedido, clienteId, region, fecha y total. Las consultas más frecuentes filtran por región y fecha.

Reto: selecciona una shard key adecuada, habilita el sharding para la base de datos y prepara la colección. Explica en una línea por qué la clave propuesta favorece las consultas y la distribución.
Solución de referencia

Una clave compuesta { region: 1, fecha: 1 } permite direccionar consultas por región y acotar rangos temporales. En producción se debe revisar su cardinalidad y distribución real para evitar puntos calientes.

// Ejecutar mediante mongos con permisos administrativos
sh.enableSharding("ventas")

// Crear el índice que respalda la shard key
db.pedidos.createIndex({ region: 1, fecha: 1 })

// Fragmentar la colección usando la clave compuesta
sh.shardCollection("ventas.pedidos", { region: 1, fecha: 1 })

// Verificar estado
sh.status()
Idea clave: CRUD modifica documentos; sharding distribuye los documentos entre nodos. La elección de la shard key debe basarse en los patrones de consulta y en una distribución equilibrada.

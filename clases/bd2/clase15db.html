1. Diseñar desde la consulta

Antes de escribir CREATE TABLE, redacta la consulta que la aplicación debe resolver. Los campos que localizan el grupo forman la clave de partición; los que ordenan, identifican o acotan filas dentro de ese grupo son columnas de agrupamiento.

Pregunta: listar los intentos de un estudiante en un examen,
          desde el más reciente hasta el más antiguo.

PRIMARY KEY ((estudiante_id, examen_id), fecha_intento, intento_id)
             └──── clave de partición ────┘  └── agrupamiento ──┘
Regla de trabajo: la consulta incluye la clave de partición completa y respeta el orden de las columnas de agrupamiento. Si una pregunta comienza con otra clave de acceso, se diseña otra tabla; ALLOW FILTERING no reemplaza un buen modelo.

2. Ejercicio guiado: intentos de evaluación

Modalidad: el docente conduce cada decisión y solicita propuestas antes de revelar el siguiente bloque. Los estudiantes ejecutan los comandos en cqlsh.

Caso

Una plataforma debe mostrar los intentos de un estudiante para un examen, del más reciente al más antiguo, y consultar los intentos realizados desde una fecha.

Datos: estudiante, examen, identificador del intento, fecha, puntaje, duración y estado.

1Convertir el requisito en una clave

El grupo responde: ¿qué valores conoce la pantalla?, ¿qué filas deben quedar juntas?, ¿qué campo determina el orden?, ¿cómo se distinguen intentos con igual fecha?

Partición: estudiante_id + examen_idAgrupamiento: fecha_intento + intento_id

La combinación estudiante–examen localiza una partición acotada. La fecha ordena e intento_id garantiza unicidad.

2Crear el esquema
CREATE KEYSPACE IF NOT EXISTS evaluaciones
WITH REPLICATION = {
  'class': 'SimpleStrategy',
  'replication_factor': 1
};

USE evaluaciones;

CREATE TABLE IF NOT EXISTS intentos_por_estudiante_examen (
  estudiante_id uuid,
  examen_id uuid,
  fecha_intento timestamp,
  intento_id timeuuid,
  puntaje decimal,
  duracion_segundos int,
  estado text,
  PRIMARY KEY ((estudiante_id, examen_id), fecha_intento, intento_id)
) WITH CLUSTERING ORDER BY (fecha_intento DESC, intento_id DESC);

SimpleStrategy se usa aquí solo para un laboratorio de un nodo.

4Read: leer la partición y un rango
-- La salida respeta el orden DESC definido en la tabla
SELECT fecha_intento, intento_id, puntaje, estado
FROM intentos_por_estudiante_examen
WHERE estudiante_id = 11111111-1111-4111-8111-111111111111
  AND examen_id = aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa;

SELECT fecha_intento, intento_id, puntaje
FROM intentos_por_estudiante_examen
WHERE estudiante_id = 11111111-1111-4111-8111-111111111111
  AND examen_id = aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa
  AND fecha_intento >= '2026-10-21 00:00:00+0000';

La primera consulta devuelve dos filas; la segunda, solamente el intento del 22 de octubre.

5Update, Delete y verificación
UPDATE intentos_por_estudiante_examen
SET puntaje = 90.0, estado = 'REVISADO'
WHERE estudiante_id = 11111111-1111-4111-8111-111111111111
  AND examen_id = aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa
  AND fecha_intento = '2026-10-22 16:30:00+0000'
  AND intento_id = 22222222-aaaa-11f0-8000-000000000002;

DELETE FROM intentos_por_estudiante_examen
WHERE estudiante_id = 11111111-1111-4111-8111-111111111111
  AND examen_id = aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa
  AND fecha_intento = '2026-10-20 14:00:00+0000'
  AND intento_id = 11111111-aaaa-11f0-8000-000000000001;

SELECT * FROM intentos_por_estudiante_examen
WHERE estudiante_id = 11111111-1111-4111-8111-111111111111
  AND examen_id = aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa;

Debe quedar una fila con puntaje 90.0 y estado REVISADO. La clave primaria no se modifica con SET; cambiarla requiere insertar la nueva fila y eliminar la anterior.

3. Ejercicios para trabajo autónomo

En cada ejercicio entrega: consulta en lenguaje natural, tabla, justificación de la clave, dos inserciones, una lectura, una actualización, una eliminación y una lectura final.

Ejercicio 1 • Básico
Historial de préstamos

Lista los préstamos de un usuario durante un año, del más reciente al más antiguo. Usa usuario_id, anio, fecha_prestamo, prestamo_id, isbn, titulo y estado. Actualiza un préstamo a DEVUELTO y elimina otro.

(usuario_id, anio) limita el historial a una partición anual; fecha y UUID ordenan e identifican.

CREATE TABLE prestamos_por_usuario_anio (
  usuario_id uuid, anio int, fecha_prestamo timestamp,
  prestamo_id uuid, isbn text, titulo text, estado text,
  PRIMARY KEY ((usuario_id, anio), fecha_prestamo, prestamo_id)
) WITH CLUSTERING ORDER BY (fecha_prestamo DESC, prestamo_id ASC);

SELECT * FROM prestamos_por_usuario_anio
WHERE usuario_id=? AND anio=?;

-- UPDATE y DELETE incluyen usuario_id, anio,
-- fecha_prestamo y prestamo_id para identificar una fila.
Ejercicio 2 • Intermedio
Lecturas de sensores por día

Muestra las lecturas de un sensor para un día y consulta el intervalo de 08:00 a 12:00. Usa sensor_id, dia, momento, lectura_id, temperatura, humedad y bateria. Corrige una lectura y elimina otra.

El sensor y el día forman una partición acotada; momento admite el rango.

CREATE TABLE lecturas_por_sensor_dia (
  sensor_id uuid, dia date, momento timestamp, lectura_id timeuuid,
  temperatura decimal, humedad decimal, bateria int,
  PRIMARY KEY ((sensor_id, dia), momento, lectura_id)
) WITH CLUSTERING ORDER BY (momento ASC, lectura_id ASC);

SELECT * FROM lecturas_por_sensor_dia
WHERE sensor_id=? AND dia='2026-10-23'
  AND momento >= '2026-10-23 08:00:00+0000'
  AND momento <= '2026-10-23 12:00:00+0000';
Ejercicio 3 • Reto
Pedidos por cliente y por identificador

La tienda debe A) listar pedidos de un cliente por mes, del más reciente, y B) abrir un pedido por pedido_id sin conocer cliente ni mes. Diseña una tabla para cada consulta. Inserta, actualiza y elimina el mismo pedido en ambas.

Los accesos son distintos: se duplican datos y la aplicación mantiene ambas representaciones.

CREATE TABLE pedidos_por_cliente_mes (
  cliente_id uuid, mes text, fecha_pedido timestamp,
  pedido_id uuid, total decimal, estado text,
  PRIMARY KEY ((cliente_id, mes), fecha_pedido, pedido_id)
) WITH CLUSTERING ORDER BY (fecha_pedido DESC, pedido_id ASC);

CREATE TABLE pedido_por_id (
  pedido_id uuid PRIMARY KEY,
  cliente_id uuid, mes text, fecha_pedido timestamp,
  total decimal, estado text
);

SELECT * FROM pedidos_por_cliente_mes
WHERE cliente_id=? AND mes=?;

SELECT * FROM pedido_por_id
WHERE pedido_id=?;

-- Si solo se actualiza una tabla, las dos vistas
-- del pedido quedan inconsistentes.

4. Lista de cotejo

CriterioEvidenciaValor
Patrón de consultaCoincide con el SELECT.20%
Clave de particiónDistribuye y limita el crecimiento.25%
AgrupamientoAdmite orden y rangos.20%
CRUDLas cuatro operaciones usan claves correctas.25%
VerificaciónUna lectura final demuestra los cambios.10%
Errores a corregir: omitir parte de una clave de partición compuesta, filtrar por una columna regular, saltar la primera columna de agrupamiento, cambiar una clave primaria con UPDATE o depender de ALLOW FILTERING.

5. Cierre

Una clave de partición localiza el conjunto; las columnas de agrupamiento lo ordenan; y el CRUD respeta esa estructura. Cuando cambia el camino de acceso, normalmente cambia la tabla.

Pregunta de salida: si una tabla consulta por (cliente_id, mes), ¿por qué no puede buscar eficientemente solo por estado? Indica qué tabla adicional crearías y qué costo introduce duplicar datos.

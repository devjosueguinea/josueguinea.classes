Consultas Avanzadas y Operadores Lógicos

Objetivos de Aprendizaje

Al finalizar esta sesión, serás capaz de construir consultas no relacionales complejas combinando condiciones booleanas, inspeccionando la existencia y tipos de atributos, buscando patrones en cadenas de texto mediante expresiones regulares, y filtrando documentos basados en la composición de arreglos y subdocumentos complejos.

Equivalencias: SQL vs MongoDB

A diferencia de SQL donde los operadores se declaran en lenguaje natural (AND, OR, LIKE), en MongoDB las expresiones lógicas y de comparación avanzada se declaran utilizando operadores prefijados por el signo de dólar ($) como llaves de objetos JSON.

Operación Sintaxis SQL Operador MongoDB Ejemplo en MongoDB
Y Lógico Cond1 AND Cond2 $and { $and: [ { precio: { $gt: 10 } }, { stock: { $gt: 0 } } ] }
O Lógico Cond1 OR Cond2 $or { $or: [ { categoria: "Tecnología" }, { precio: { $lt: 50 } } ] }
Negación Lógica NOT (Condición) $not { precio: { $not: { $gt: 100 } } }
Pertenencia a Lista columna IN (val1, val2) $in { categoria: { $in: ["Muebles", "Hogar"] } }
No Pertenencia a Lista columna NOT IN (val1, val2) $nin { categoria: { $nin: ["Alimentos", "Salud"] } }
Búsqueda por Patrón columna LIKE '%texto%' $regex { nombre: { $regex: "teclado", $options: "i" } }
Existencia de Atributo columna IS NOT NULL $exists { descuento: { $exists: true } }

1. Operadores de Filtros Avanzados

Operadores Lógicos

Permiten formular composiciones lógicas complejas sobre los documentos:

  • $or: Selecciona documentos que cumplan al menos una de las condiciones especificadas en un arreglo.
  • $and: Une cláusulas de consulta con un AND lógico. Nota: Por defecto, MongoDB realiza un $and implícito cuando separas campos por comas. El operador explícito se usa cuando se requiere consultar el mismo operador o campo múltiples veces.
  • $nor: Devuelve los documentos que fallan en cumplir todas las condiciones dadas.
  • $not: Invierte el resultado de una expresión evaluadora de comparación.
Operadores de Arreglos

MongoDB permite que los campos contengan arreglos nativos. Para consultarlos de manera efectiva contamos con:

  • $all: El campo del arreglo debe contener todos los elementos especificados en la consulta, independientemente del orden.
  • $size: Filtra documentos si el arreglo del campo tiene exactamente el tamaño especificado.
  • $elemMatch: Crucial para consultar arreglos de subdocumentos. Asegura que al menos un objeto del arreglo cumpla con todas las condiciones especificadas, evitando evaluaciones cruzadas entre distintos elementos.

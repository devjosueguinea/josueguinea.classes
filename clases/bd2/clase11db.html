1. Resumen Ejecutivo de Clases 7, 8, 9 y 10

Clase 7
Aggregation Pipeline

Procesamiento por etapas secuenciales sobre colecciones de MongoDB.

  • $match: Filtrado temprano de documentos.
  • $group: Agregación con $sum, $avg, $first.
  • $unwind: Aplanado de arrays de subdocumentos.
  • $lookup: Joins entre colecciones.
Clase 8
Modelado de Datos

Decisión entre Incrustación (Embedding) y Referencia (Referencing).

  • Embedding: Rendimiento de lectura atómico, relación 1:1 y 1:N contenido.
  • Referencing: Evita duplicación masiva en relaciones 1:N grandes y N:M.
  • Límite atómico BSON: 16 MB por documento.
Clase 9
Sharding e Índices

Escalabilidad horizontal mediante particionado de datos en clusters.

  • Componentes: mongos (Router), Config Servers, Shards.
  • Shard Key: Elección basada en Rango vs Hashed vs Compuesta.
  • Índices Compuestos: Regla ESR (Equality, Sort, Range).
Clase 10
Patrones de Diseño

Soluciones avanzadas para casos de uso reales en producción NoSQL.

  • Bucket Pattern: Agrupación por intervalos de tiempo (IoT/Logs).
  • Outlier Pattern: Manejo de excepciones fuera de la norma.
  • Pre-computation: Métricas calculadas previamente.

Taller Guiado: Conexión y Analítica de MongoDB en Power BI Desktop

Business Intelligence NoSQL

En las organizaciones modernas, las aplicaciones transaccionales operan sobre MongoDB en estructuras NoSQL flexibles (JSON/BSON). Sin embargo, las herramientas analíticas corporativas como Power BI requieren modelos relacionales tubulares (Tablas, Filas y Columnas). Aprende la arquitectura y los pasos para integrar ambas tecnologías.

Opción A: MongoDB BI Connector (mongosqld)

Componente de software de MongoDB que traduce SQL entrante emitido por Power BI a consultas NoSQL de Aggregation Pipeline en tiempo real.

  • Proporciona un esquema relacional virtual mapeando BSON a tablas.
  • Conexión mediante Driver ODBC de MySQL/MongoDB.
  • Soporta modos de importación DirectQuery e Import en Power BI.
Opción B: MongoDB Atlas SQL Connector / Power Query M

Conector nativo disponible para clusters en la nube (MongoDB Atlas SQL Interface) o importación directa JSON.

  • Conexión segura vía TLS/SSL directamente a la URI de Atlas.
  • Desanidado visual de documentos complejos mediante Power Query M.
  • Transformación de arrays con Table.ExpandListColumn.
Pasos de Transformación en Power Query M (Desanidado JSON):
Paso 1
Obtener Datos

Conectar a MongoDB mediante conector ODBC o Atlas SQL especificando Server y Database.

Paso 2
Expandir Record

En el editor de Power Query, seleccionar el icono de expansión en la columna `Value` para desglosar subdocumentos.

Paso 3
Expandir en Filas

Para campos que contienen arreglos (Lists), seleccionar "Expandir a nuevas filas" equivalentemente al $unwind de MongoDB.

Paso 4
Modelado en Estrella

Definir tipos de datos (Fecha, Moneda, Entero) y crear relaciones entre la Tabla de Hechos y Dimensiones.

Ejercicio 1: Agregación Analítica de Ventas para Tablero de Power BI

Complejidad Intermedia

Enunciado: Se cuenta con una colección de documentos de ventas en MongoDB con la siguiente estructura: 

{
  "_id": ObjectId("65a1f2b..."),
  "sucursal": "Centro",
  "fecha": ISODate("2026-02-15T10:30:00Z"),
  "estado": "Completado",
  "productos": [
    { "sku": "PROD-01", "categoria": "Electrónica", "cantidad": 2, "precio_unitario": 150.00 },
    { "sku": "PROD-09", "categoria": "Accesorios", "cantidad": 1, "precio_unitario": 25.00 }
  ]
}

Requerimiento: Escribe una pipeline de agregación en MongoDB que prepare la información para exponer a Power BI calculando: 1. Filtrar solo las ventas con estado "Completado". 2. Desanidar el arreglo de productos. 3. Agrupar por sucursal y categoria. 4. Calcular el Total de Ingresos (multiplicando cantidad * precio_unitario) y la Cantidad Total de Productos Vendidos.

Utiliza las etapas $match, $unwind, $group y operadores aritméticos en $group.
Pipeline de Agregación MongoDB Resuelta:
db.ventas.aggregate([
  // Etapa 1: Filtrar solo ventas completadas
  {
    $match: { "estado": "Completado" }
  },
  // Etapa 2: Desanidar el arreglo de productos ($unwind)
  {
    $unwind: "$productos"
  },
  // Etapa 3: Agrupar por sucursal y categoría
  {
    $group: {
      _id: {
        sucursal: "$sucursal",
        categoria: "$productos.categoria"
      },
      ingresosTotales: {
        $sum: { $multiply: ["$productos.cantidad", "$productos.precio_unitario"] }
      },
      unidadesVendidas: {
        $sum: "$productos.cantidad"
      }
    }
  },
  // Etapa 4: Formatear la salida para consumo plano en Power BI
  {
    $project: {
      _id: 0,
      sucursal: "$_id.sucursal",
      categoria: "$_id.categoria",
      ingresosTotales: 1,
      unidadesVendidas: 1
    }
  }
]);

Explicación Analítica: Esta pipeline transforma documentos anidados de alta flexibilidad en un conjunto plano tridimensional (Sucursal | Categoría | Ingresos | Unidades), permitiendo a Power BI importar únicamente el resultado agregado súper rápido.

Ejercicio 2: Estrategia de Sharding y Diseños para Analytics a Gran Escala

Complejidad Intermedia

Enunciado: Una empresa de telemetría IoT recopila 50 millones de lecturas mensuales de sensores de temperatura (sensor_id, fecha, lectura, ubicacion). Power BI consulta constantemente tableros ejecutivos agregando promedios diarios por ubicacion.

Preguntas de Diseño NoSQL:
  1. ¿Qué patrón de diseño NoSQL (Clase 10) se debe aplicar para consolidar estas mediciones por hora/día y evitar el desbordamiento de lecturas individuales?
  2. Si se configura Sharding en el cluster de MongoDB (Clase 9), ¿qué Shard Key compuestas sugieres para balancear la carga de escritura masiva y permitir consultas analíticas eficientes desde Power BI?
Analiza la cardinalidad de la clave y el principio de consultas dirigidas (Targeted Queries).
Solución de Diseño de Arquitectura NoSQL:
  • 1. Patrón de Diseño Recomendado: Aplicar el Bucket Pattern (Patrón Cubeta). En lugar de almacenar 1 documento por cada lectura del sensor cada segundo, se agrupan las mediciones de 1 hora dentro de un mismo documento con un arreglo de lecturas y métricas pre-calculadas (sum_temperatura, count_lecturas). Esto reduce el volumen de documentos de 50 millones a solo 700,000 por mes.
  • 2. Selección de la Shard Key: Una clave de fragmentación compuesta ideal es: { "ubicacion": 1, "fecha": 1 } Justificación: La combinación de ubicacion (alta cardinalidad por zonas) con fecha distribuye uniformemente la escritura continua entre los shards del cluster y permite que las consultas de Power BI dirigidas por región se enruten directamente al shard específico (Targeted Query) sin golpear a todo el cluster (Scatter-Gather).

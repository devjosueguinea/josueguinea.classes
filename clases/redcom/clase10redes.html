1. Fundamentos Teóricos e Historia del Modelo TCP/IP

¿Qué es el Modelo TCP/IP?

El modelo TCP/IP (Protocolo de Control de Transmisión / Protocolo de Internet) es un conjunto jerárquico de protocolos de comunicación diseñado en la década de 1970 por el Departamento de Defensa de los EE. UU. (DoD - DARPA) a través de investigadores como Vinton Cerf y Robert Kahn.

A diferencia del Modelo OSI, que se creó como una referencia teórica conceptual, TCP/IP fue diseñado como una solución práctica e implementable para interconectar redes heterogéneas (satélite, radio, cable coaxial, enlaces dedicados) garantizando que la red continúe funcionando aun cuando nodos intermedios sean destruidos o fallen.

Documentación RFC: Las especificaciones de TCP/IP no se publican como libros cerrados, sino mediante RFCs (Request for Comments) abiertos mantenidos por el IETF (Internet Engineering Task Force). Por ejemplo: RFC 791 (IPv4), RFC 793 (TCP) y RFC 768 (UDP).
Principios de Diseño Fundamentales
  • Principio Extremo a Extremo (End-to-End): La inteligencia y el control de errores residen en los hosts finales, manteniendo el núcleo de la red simple y eficiente.
  • Conmutación de Paquetes (Packet Switching): Los mensajes se fragmentan en paquetes independientes que pueden viajar por diferentes rutas dinámicas.
  • Tolerancia a Fallos e Independencia del Medio: Funcionamiento agnóstico sobre cualquier tecnología física (Ethernet, Fibra Óptica, Wi-Fi, LTE/5G).

2. Desglose de las 4 Capas del Modelo TCP/IP

El modelo original del DoD define 4 capas superpuestas. A continuación se analiza detalladamente cada nivel, sus funciones, unidades de datos (PDU) y protocolos representativos:

Capa 4: Aplicación
PDU: Datos / Mensaje

Representa la interfaz directa para los procesos de software del usuario final. Engloba las funciones que en OSI se dividen en Aplicación, Presentación y Sesión (cifrado, compresión y diálogo).

Protocolos Principales:
HTTP / HTTPS (80/443) DNS (53) DHCP (67/68) FTP / SFTP (21/22) SSH (22) SMTP / POP3 / IMAP
Capa 3: Transporte
PDU: Segmento (TCP) / Datagrama (UDP)

Garantiza la comunicación origen a destino entre aplicaciones mediante el uso de Números de Puerto. Maneja la multiplexación, control de flujo y confiabilidad.

Protocolos Principales:
TCP (Transmission Control Protocol) UDP (User Datagram Protocol)

Concepto Clave: Socket = Dirección IP + Número de Puerto (Ejemplo: 192.168.1.10:443).

Capa 2: Internet
PDU: Paquete IP

Responsable del direccionamiento lógico universal y la determinación de rutas (enrutamiento) para trasladar paquetes a través de múltiples redes interconectadas.

Protocolos Principales:
IPv4 / IPv6 ICMP (Ping / Traceroute) ARP (Address Resolution Protocol) IPsec
Capa 1: Acceso a la Red
PDU: Trama (Frame) y Bits

Especifica el formato con el que los datos deben estructurarse para ser transmitidos sobre los medios físicos y gestiona la entrega en el enlace local mediante direcciones físicas MAC.

Tecnologías y Estándares:
Ethernet (IEEE 802.3) Wi-Fi (IEEE 802.11) PPP / Frame Relay Drivers y Controladores NIC

3. Protocolos de Transporte: TCP vs UDP & Handshake

TCP (Transmission Control Protocol)
Confiable
  • Orientado a Conexión: Requiere negociación previa (Handshake) antes de enviar datos.
  • Garantía de Entrega: Reenvía paquetes perdidos mediante confirmaciones (ACKs).
  • Secuenciamiento: Reordena los segmentos en el receptor según el número de secuencia.
  • Control de Flujo: Ajusta la velocidad mediante Ventanas Deslizantes (Sliding Window).
UDP (User Datagram Protocol)
Rápido / Best-Effort
  • Sin Conexión: Envía datagramas inmediatamente sin establecer sesión.
  • Sin Confiabilidad incorporada: No realiza retransmisiones ni exige confirmación ACK.
  • Mínimo Overhead: Cabecera ultra ligera de solo 8 bytes (frente a los 20 bytes de TCP).
  • Aplicaciones: Streaming de video/audio, VoIP, Juegos online, DNS, DHCP.
El Handshake de 3 Vías de TCP (Three-Way Handshake)

Para iniciar una transferencia confiable, el cliente y el servidor sincronizan sus números de secuencia iniciales (ISN) mediante 3 pasos fundamentales:

Paso 1: SYN
Cliente → Servidor

"Quiero conectarme. Mi número de secuencia inicial es Seq = X."

Paso 2: SYN-ACK
Servidor → Cliente

"Recibido tu SYN (Ack = X+1). Yo acepto y mi secuencia es Seq = Y."

Paso 3: ACK
Cliente → Servidor

"Recibido tu SYN (Ack = Y+1). ¡Conexión Establecida!"

4. Cuadro Comparativo Profundo: Modelo TCP/IP vs Modelo OSI

Analiza detalladamente las convergencias, diferencias estructurales y equivalencias operativas entre el modelo académico OSI (7 capas) y la arquitectura funcional TCP/IP (4 capas).

Modelo OSI (7 Capas) Modelo TCP/IP (4 Capas) PDU / Unidades Diferencias y Criterios Operativos
7. Aplicación
6. Presentación
5. Sesión
Capa 4: Aplicación
Datos / Mensaje TCP/IP combina el formato (Presentación) y control de sesión dentro de los propios protocolos de aplicación (HTTP, SSH, TLS/SSL).
4. Transporte
Capa 3: Transporte
Segmento / Datagrama Misma función conceptual. TCP/IP ofrece la elección estricta entre protocolo confiable (TCP) o liviano (UDP).
3. Red
Capa 2: Internet
Paquete IP OSI soporta servicios de red con y sin conexión. En TCP/IP, el protocolo IP es estrictamente sin conexión (Connectionless).
2. Enlace de Datos
1. Física
Capa 1: Acceso a la Red
Trama (Frame) y Bits TCP/IP no especifica protocolos físicos específicos; delega el entramado y señalización a los estándares de hardware de red (Ethernet, Wi-Fi).
Modelo OSI (Estándar De Jure)
  • Desarrollado por la ISO como marco de referencia teórico.
  • Distinción estricta entre servicios, interfaces y protocolos.
  • Llegó tarde al mercado comercial; complejo de implementar íntegramente.
Modelo TCP/IP (Estándar De Facto)
  • Desarrollado con fondos del DoD basándose en código real (Unix BSD).
  • Protocolos definidos antes que el modelo teórico.
  • Dominante en la industria e infraestructura global de Internet.

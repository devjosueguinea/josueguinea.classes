Reto 1: Topología de Estrella y Conectividad Básica

Diseña en Cisco Packet Tracer una topología que contenga 3 PCs y 1 Servidor Web conectados a un Switch 2960. Define el direccionamiento IP de red privada local y verifica la conectividad.

Solución Recomendada:
  • Conexiones físicas: Utiliza cables directos (Copper Straight-Through) desde la interfaz FastEthernet de cada PC y el Servidor hacia cualquier puerto libre del Switch 2960.
  • Direccionamiento IP: Asigna IPs fijas en el mismo rango de red local, por ejemplo:
    • PC1: 192.168.1.10 (Máscara: 255.255.255.0)
    • PC2: 192.168.1.11 (Máscara: 255.255.255.0)
    • PC3: 192.168.1.12 (Máscara: 255.255.255.0)
    • Servidor Web: 192.168.1.100 (Máscara: 255.255.255.0)
  • Verificación: Entra al símbolo del sistema (Command Prompt) de PC1 y ejecuta ping 192.168.1.100. Luego, abre el navegador web de PC2 e ingresa 192.168.1.100 para visualizar la página web por defecto del Servidor.
Sistema Binario
Reto 2: Conversión de Máscara de Subred

Un administrador de red ha configurado la máscara de subred decimal 255.255.240.0. Conviértela a su representación en código binario y obtén su prefijo CIDR.

Solución Recomendada:
  • Conversión de octetos:
    • 255 → 11111111
    • 255 → 11111111
    • 240 → 11110000 (128+64+32+16 = 240)
    • 0 → 00000000
  • Representación Binaria Completa: 11111111.11111111.11110000.00000000
  • Prefijo CIDR: Cuenta el número de bits encendidos (1s). En este caso hay 8 + 8 + 4 = 20 bits. Por lo tanto, el prefijo CIDR equivalente es /20.

Reto 3: Identificación de Parámetros de Red

Dada la dirección IP de host 172.16.45.101/22, calcula la dirección de red a la que pertenece, su broadcast y el rango de IPs utilizables.

Solución Recomendada:
  • Máscara /22: Corresponde a 255.255.252.0. En el tercer octeto, el tamaño de bloque es $2^{32-22} = 2^{10} \rightarrow 1024$ direcciones totales ($256 \times 4$), indicando saltos de 4 en el tercer octeto.
  • Determinación del bloque: Las redes saltan en `172.16.0.0`, `172.16.4.0`, ..., `172.16.40.0`, `172.16.44.0`, `172.16.48.0`. La IP `172.16.45.101` cae en el rango de la red 172.16.44.0.
  • Parámetros Resultantes:
    • Dirección de Red: 172.16.44.0
    • Primera IP Utilizable: 172.16.44.1
    • Última IP Utilizable: 172.16.47.254
    • Dirección de Broadcast: 172.16.47.255

Reto 4: Enlace Físico entre Routers

Debes conectar directamente dos Routers 2911 en tu simulación utilizando sus interfaces GigabitEthernet. ¿Qué tipo de cable físico es el correcto y qué secuencia de comandos Cisco IOS se requiere para levantar las interfaces?

Solución Recomendada:
  • Cable Físico: Para conectar dos dispositivos de la misma capa (Router a Router) se debe utilizar un cable cruzado (Copper Cross-Over), aunque en dispositivos modernos la tecnología Auto-MDIX permita cables directos.
  • Secuencia de Comandos (en ambos routers): 
    Router> enable
Router# configure terminal
Router(config)# interface GigabitEthernet 0/0
Router(config-if)# ip address 10.0.0.1 255.255.255.252 (Ejemplo Router 1)
Router(config-if)# no shutdown
Router(config-if)# exit

Reto 5: Dirección IPv4 a Binario Puro

Convierte la dirección IP de host 10.254.13.99 a formato binario de 32 bits, estructurada en 4 octetos.

Solución Recomendada:
  • Conversión por Octetos:
    • 10 → 00001010 (8 + 2)
    • 254 → 11111110 (255 - 1)
    • 13 → 00001101 (8 + 4 + 1)
    • 99 → 01100011 (64 + 32 + 2 + 1)
  • Dirección IP en Binario: 00001010.11111110.00001101.01100011

Reto 6: Gateway Predeterminado (Default Gateway)

Una topología posee una red local en el segmento 192.168.50.0/24. El Router tiene asignada la IP 192.168.50.254 en la interfaz LAN. ¿Qué configuración de Gateway debes aplicar en las PCs locales y por qué es indispensable?

Solución Recomendada:
  • Configuración: Se debe asignar la dirección IP 192.168.50.254 como Default Gateway en la pestaña IP Configuration de cada PC de la red.
  • Propósito: El Gateway es la IP de la interfaz del router que actúa como "puerta de salida". Sin esta configuración, los hosts de la red local solo podrán hacer ping entre ellos, pero no podrán enviar tráfico hacia redes remotas, internet o servidores externos.

Reto 7: Simulación de Servidor DHCP

Describe cómo configurar un Servidor genérico en Packet Tracer para entregar direccionamiento IP de forma dinámica a una LAN en el segmento 192.168.10.0/24 iniciando desde la dirección 192.168.10.50.

Solución Recomendada:
  • Configurar IP Estática en el Servidor: Asigna por ejemplo 192.168.10.2 con máscara 255.255.255.0 y Gateway 192.168.10.1.
  • Configurar el servicio DHCP:
    • Haz clic en el Servidor → pestaña Services → selecciona DHCP.
    • Activa el servicio (marcar On).
    • Ingresa el Default Gateway: 192.168.10.1.
    • Configura "Start IP Address" como: 192.168.10.50.
    • Guarda los cambios (clic en Save).
  • Verificación en los hosts: Ve a cualquier PC → Desktop → IP Configuration → cambia de "Static" a "DHCP". Comprueba que reciba una IP dentro de la secuencia (ej. 192.168.10.50, 192.168.10.51, etc.).

Reto 8: Cálculo de Bits para Hosts

Una empresa requiere subredes con capacidad para albergar al menos 120 hosts reales cada una, a partir de la red 192.168.100.0/24. ¿Cuántos bits de host ($h$) y bits de subred ($s$) se deben asignar?

Solución Recomendada:
  • Calcular bits de host ($h$): Usamos la fórmula: $2^h - 2 \ge 120$.
    • Si $h=6 \rightarrow 2^6 - 2 = 62$ (insuficiente).
    • Si $h=7 \rightarrow 2^7 - 2 = 126$ (suficiente).
    Por ende, requerimos 7 bits de host.
  • Calcular bits de subred ($s$): La red base original /24 nos deja 8 bits para hosts ($32 - 24 = 8$). Si reservamos 7 para hosts, nos queda: $s = 8 - 7 = 1$ bit.
    • Bits de Subred ($s$): 1 bit prestado.
    • Nueva máscara: 24 + 1 = /25 (equivalente a 255.255.255.128).
    • Subredes creadas: $2^1 = 2$ subredes de 126 hosts útiles cada una.

Reto 9: Identificación de IPs Especiales

Explica detalladamente por qué las direcciones 127.0.0.1 y 169.254.10.15 no deben asignarse de forma estática como IPs utilizables en servidores de producción.

Solución Recomendada:
  • 127.0.0.1 (Dirección de Loopback): Reservada para pruebas locales del software de red dentro del propio equipo. No viaja a través del medio físico, por lo que es inaccesible externamente.
  • 169.254.X.X (APIPA - Automatic Private IP Addressing): Este rango es autoasignado por sistemas operativos (Windows) cuando una interfaz configurada en modo DHCP no logra obtener comunicación con un servidor DHCP. Indica una falla de comunicación en la capa física o de servicios, y no es enrutable.

Reto 10: Configuración de Router Inalámbrico de Hogar

Configura un Router inalámbrico casero (Home Gateway) en Packet Tracer. Conecta una PC vía cable y un Smartphone vía Wi-Fi. Explica el procedimiento para ingresar a la interfaz gráfica y cambiar el SSID.

Solución Recomendada:
  • Conexión Física y Lógica: Conecta la PC a uno de los puertos Ethernet (LAN) del Home Gateway. El Gateway asignará de forma automática una IP por DHCP a la PC (ej. 192.168.0.100) y su IP LAN será la IP de Default Gateway (ej. 192.168.0.1).
  • Acceso a la Interfaz Gráfica (GUI): Abre la PC simulada → pestaña Desktop → Web Browser. En la barra de direcciones escribe la IP del router: 192.168.0.1.
  • Credenciales y Configuración: Introduce las credenciales por defecto (usuario: admin, contraseña: admin). Dirígete a la sección Wireless → cambia el "Wireless Network Name (SSID)" al nombre deseado y guarda los cambios.
